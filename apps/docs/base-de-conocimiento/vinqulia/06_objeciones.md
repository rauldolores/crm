# Vinqulia — Biblioteca de objeciones

Regla crítica: nunca inventar una respuesta cuando no exista información oficial — marcar `[REQUIERE CONFIRMACIÓN INTERNA]` y ofrecer escalar. Ver [[12_escalamiento]].

```
OBJECIÓN: "Está caro."
Qué puede significar realmente: no ve el valor todavía, o está comparando contra un precio que no conoce con certeza.
Respuesta recomendada: entender qué está comparando y mostrar el problema que resuelve antes de discutir cifras. Ver [[10_precios-y-planes]].
Pregunta de seguimiento: "¿Comparado con qué? ¿Ya tienes una cotización de otra opción?"
Error que debe evitarse: dar un descuento o justificar el precio sin haber cotizado formalmente.
Cuándo escalar: en cuanto el cliente quiera negociar una cifra concreta.
```

```
OBJECIÓN: "Ya tenemos CRM."
Qué puede significar realmente: puede estar satisfecho, o puede estar evaluando alternativas sin decirlo directamente.
Respuesta recomendada: preguntar qué tan bien les está funcionando ese CRM hoy, sin atacarlo.
Pregunta de seguimiento: "¿Qué es lo que menos te gusta de tu CRM actual?"
Error que debe evitarse: hablar mal del competidor. Ver [[07_competidores]].
Cuándo escalar: si el cliente pide una comparación técnica detallada.
```

```
OBJECIÓN: "Ya usamos HubSpot."
Qué puede significar realmente: satisfacción real, o frustración con el costo/complejidad que no ha verbalizado.
Respuesta recomendada: "Depende de lo que necesites" — preguntar qué le funciona y qué no de HubSpot.
Pregunta de seguimiento: "¿Qué parte de HubSpot sientes que no estás aprovechando?"
Error que debe evitarse: afirmar que Vinqulia es superior a HubSpot en general.
Cuándo escalar: si pide una comparación de funcionalidades punto por punto.
```

```
OBJECIÓN: "Ya usamos Pipedrive."
Qué puede significar realmente: igual que con HubSpot — puede ser satisfacción o una frustración no dicha.
Respuesta recomendada: preguntar qué tan bien resuelve Pipedrive su caso específico hoy.
Pregunta de seguimiento: "¿Qué te haría considerar un cambio?"
Error que debe evitarse: comparaciones inventadas sobre funcionalidades de Pipedrive.
Cuándo escalar: si pide una comparación de funcionalidades punto por punto.
```

```
OBJECIÓN: "Tenemos Excel."
Qué puede significar realmente: cree que su volumen no justifica un CRM, o no conoce el costo real de seguir en Excel.
Respuesta recomendada: preguntar por los síntomas típicos (versiones distintas, datos perdidos). Ver [[03_problemas-soluciones]].
Pregunta de seguimiento: "¿Cuántas personas tocan hoy ese archivo?"
Error que debe evitarse: menospreciar Excel como herramienta — validar que funcionó hasta ahora.
Cuándo escalar: no aplica, salvo que la conversación derive en otra objeción de la lista.
```

```
OBJECIÓN: "No quiero cambiar."
Qué puede significar realmente: temor al costo de migración, a la curva de aprendizaje, o a que el equipo no lo adopte.
Respuesta recomendada: identificar cuál de esos miedos es el real antes de responder.
Pregunta de seguimiento: "¿Qué es lo que más te preocupa de hacer un cambio?"
Error que debe evitarse: presionar o minimizar la resistencia al cambio.
Cuándo escalar: si el miedo es sobre pérdida de datos específicos — puede requerir validación técnica.
```

```
OBJECIÓN: "Mi equipo no va a usarlo."
Qué puede significar realmente: experiencia previa con un sistema complejo que el equipo rechazó.
Respuesta recomendada: explicar la personalización de campos, etapas y terminología al vocabulario real del equipo. Ver [[01_producto]].
Pregunta de seguimiento: "¿Qué pasó la última vez que intentaron adoptar un sistema nuevo?"
Error que debe evitarse: prometer que "esta vez sí funcionará" sin entender la causa raíz anterior.
Cuándo escalar: no aplica directamente, salvo que derive en una objeción de precio o de tiempo de implementación.
```

```
OBJECIÓN: "No quiero otro sistema."
Qué puede significar realmente: fatiga de herramientas — ya usan demasiadas plataformas distintas.
Respuesta recomendada: enfatizar que Vinqulia se integra con lo que ya usan (API, webhooks) en vez de sumar una isla más.
Pregunta de seguimiento: "¿Cuántos sistemas distintos usa hoy tu equipo comercial?"
Error que debe evitarse: minimizar la fatiga de herramientas del cliente.
Cuándo escalar: si requiere una integración específica no documentada.
```

```
OBJECIÓN: "WhatsApp ya nos funciona."
Qué puede significar realmente: no ve el riesgo de tener la información solo en el teléfono del vendedor.
Respuesta recomendada: preguntar qué pasaría si ese vendedor se va mañana.
Pregunta de seguimiento: "¿Qué pasa con esas conversaciones si el vendedor cambia de trabajo?"
Error que debe evitarse: decir que hay que dejar de usar WhatsApp — Vinqulia lo integra, no lo reemplaza.
Cuándo escalar: no aplica.
```

```
OBJECIÓN: "No necesito CRM."
Qué puede significar realmente: no ha identificado un problema concreto todavía, o su volumen actual es bajo.
Respuesta recomendada: volver a discovery — entender el proceso actual antes de insistir.
Pregunta de seguimiento: "¿Cómo describirías tu proceso de venta hoy, de principio a fin?"
Error que debe evitarse: insistir sin haber encontrado un problema real que resolver.
Cuándo escalar: no aplica — si no hay problema identificado, no forzar el avance.
```

```
OBJECIÓN: "Solo quiero saber el precio."
Qué puede significar realmente: quiere filtrar rápido si está dentro de su rango antes de invertir tiempo.
Respuesta recomendada: explicar que el precio se cotiza según necesidad y ofrecer levantar los datos mínimos para cotizar. Ver [[10_precios-y-planes]].
Pregunta de seguimiento: "Para darte un número real, ¿cuántos usuarios y qué necesidades tendrías?"
Error que debe evitarse: inventar un rango de precio no verificado.
Cuándo escalar: si insiste en un número exacto sin dar contexto, escalar a un especialista comercial.
```

```
OBJECIÓN: "Quiero probarlo."
Qué puede significar realmente: interés genuino y disposición a avanzar.
Respuesta recomendada: encaminar hacia agendar una demo con un especialista — no hay evidencia oficial de una prueba gratuita autoservicio.
Pregunta de seguimiento: "¿Prefieres que te muestre una demo con tus propios datos de ejemplo?"
Error que debe evitarse: afirmar que existe una prueba gratuita sin confirmarlo. Ver [[10_precios-y-planes]].
Cuándo escalar: no aplica — es señal de intención de compra alta, avanzar a captura de datos.
```

```
OBJECIÓN: "Necesito instalarlo en mis servidores."
Qué puede significar realmente: requisito de TI/seguridad para mantener control de los datos.
Respuesta recomendada: confirmar que existe la modalidad de infraestructura propia del cliente, además del servicio administrado.
Pregunta de seguimiento: "¿Ese requisito viene de una política interna o de una obligación regulatoria específica?"
Error que debe evitarse: dar detalles técnicos de arquitectura sin validación de un especialista.
Cuándo escalar: siempre — requisito técnico específico. Ver [[12_escalamiento]].
```

```
OBJECIÓN: "Necesito integrarlo con mi ERP."
Qué puede significar realmente: necesidad real de sincronización de datos entre sistemas.
Respuesta recomendada: confirmar que existe API REST, claves de API y webhooks como camino de integración.
Pregunta de seguimiento: "¿Qué ERP usan y qué información necesitarían sincronizar?"
Error que debe evitarse: afirmar que existe un conector prearmado a ese ERP específico sin confirmarlo.
Cuándo escalar: siempre — integración no documentada. Ver [[12_escalamiento]].
```

```
OBJECIÓN: "¿Tiene SAP?"
Qué puede significar realmente: pregunta directa sobre un conector prearmado específico.
Respuesta recomendada: no afirmar ni negar sin confirmar — ofrecer validar con un especialista.
Pregunta de seguimiento: "¿Qué información necesitarías que se sincronizara entre Vinqulia y SAP?"
Error que debe evitarse: inventar que existe integración nativa con SAP.
Cuándo escalar: siempre. Ver [[12_escalamiento]].
```

```
OBJECIÓN: "¿Tiene Salesforce?"
Qué puede significar realmente: igual que con SAP — pregunta directa sobre integración específica.
Respuesta recomendada: no afirmar ni negar sin confirmar — ofrecer validar con un especialista.
Pregunta de seguimiento: "¿Qué buscarías lograr conectando Vinqulia con Salesforce?"
Error que debe evitarse: inventar que existe integración nativa con Salesforce.
Cuándo escalar: siempre. Ver [[12_escalamiento]].
```

```
OBJECIÓN: "¿Tiene IA?"
Qué puede significar realmente: interés genérico en IA, sin un caso de uso concreto todavía.
Respuesta recomendada: distinguir lo incluido (automatizaciones, servidor MCP para conectar asistentes como Claude) de lo contratable aparte (agentes personalizados vía Kontrolia). Ver [[01_producto]].
Pregunta de seguimiento: "¿Qué te gustaría que hiciera esa IA en tu proceso comercial?"
Error que debe evitarse: prometer capacidades de IA no verificadas.
Cuándo escalar: si busca un agente/proceso de IA a medida. Ver [[12_escalamiento]].
```

```
OBJECIÓN: "¿Qué tan seguro es?"
Qué puede significar realmente: preocupación genuina de TI/seguridad, o pregunta de trámite.
Respuesta recomendada: mencionar que los datos viven en Supabase (PostgreSQL) con control de acceso por organización, y ofrecer profundizar con un especialista si necesita detalle de cumplimiento.
Pregunta de seguimiento: "¿Tienen algún requisito de cumplimiento normativo específico?"
Error que debe evitarse: afirmar certificaciones (ISO, SOC2, etc.) no confirmadas. Ver `[REQUIERE CONFIRMACIÓN INTERNA]` en [[01_producto]].
Cuándo escalar: si pide detalle de certificaciones o cumplimiento específico. Ver [[12_escalamiento]].
```

```
OBJECIÓN: "¿Dónde están los datos?"
Qué puede significar realmente: pregunta de cumplimiento o de confianza en el proveedor.
Respuesta recomendada: explicar que se puede optar por el servicio administrado o por infraestructura propia del cliente.
Pregunta de seguimiento: "¿Tienen algún requisito específico sobre la ubicación de los datos?"
Error que debe evitarse: afirmar una región/país de alojamiento no confirmado.
Cuándo escalar: si el requisito es específico (país, región). Ver [[12_escalamiento]].
```

```
OBJECIÓN: "¿Cuánto tarda la implementación?"
Qué puede significar realmente: quiere estimar cuándo vería resultados.
Respuesta recomendada: explicar que el proceso de implementación tiene pasos definidos, pero el plazo depende del alcance — no dar una cifra de tiempo no confirmada.
Pregunta de seguimiento: "¿Qué tan compleja crees que sería tu migración/configuración inicial?"
Error que debe evitarse: prometer una fecha de entrega sin validarla con el equipo de implementación.
Cuándo escalar: si pide un cronograma comprometido. Ver [[12_escalamiento]].
```

```
OBJECIÓN: "¿Puedo migrar desde otro CRM?"
Qué puede significar realmente: preocupación por perder su historial actual.
Respuesta recomendada: confirmar que existe importación CSV/JSON con detección de duplicados.
Pregunta de seguimiento: "¿Tu CRM actual te permite exportar la información en CSV o JSON?"
Error que debe evitarse: prometer una migración automática directa entre sistemas sin confirmarlo.
Cuándo escalar: si el volumen o la complejidad de la migración es alta.
```

```
OBJECIÓN: "¿Puedo personalizarlo?"
Qué puede significar realmente: viene de una mala experiencia con un sistema rígido.
Respuesta recomendada: confirmar que campos, etapas, categorías, moneda y marca son personalizables sin desarrollo. Ver [[01_producto]].
Pregunta de seguimiento: "¿Qué es específicamente lo que necesitarías personalizar?"
Error que debe evitarse: prometer una personalización que requiera desarrollo a medida sin escalarla.
Cuándo escalar: si la personalización requiere código nuevo, no configuración. Ver [[12_escalamiento]].
```

```
OBJECIÓN: "¿Cuántos usuarios soporta?"
Qué puede significar realmente: quiere saber si Vinqulia escala con el crecimiento de su equipo.
Respuesta recomendada: confirmar que el sistema es multi-tenant y pensado para crecer en usuarios y organizaciones; el límite exacto por plan no está documentado públicamente.
Pregunta de seguimiento: "¿Cuántos usuarios tienen hoy y cuántos esperan tener en un año?"
Error que debe evitarse: inventar un número máximo de usuarios. Ver [[10_precios-y-planes]].
Cuándo escalar: si necesita una cifra exacta comprometida contractualmente.
```
